# MeshCore MQTT

Свой брокер для репитеров MeshCore и две панели: пользовательская (`/app`) и администратора (`/admin`).

Устройства подключаются по MQTT поверх TLS к одному адресу, порт `8883`. Прокси читает логин и отправляет соединение на узел, где лежит тунель. Открытого порта `1883` нет.

## Запуск

```bash
docker compose up --build
```

Панель: `http://localhost:8088`

Первый администратор: `admin@localhost` / `admin`. Перед реальным использованием смените пароль, `Jwt__Key`, `Internal__Token` и `Mqtt__SuperuserPassword` в `docker-compose.yml`. Токен в compose и в шаблоне Mosquitto должен совпадать: контейнер брокера подставляет `INTERNAL_TOKEN` сам.

`Mqtt__PublicHost` задаёт имя только при первом выпуске. Дальше имя и сертификат меняются в админке, раздел «Сертификат»: новый сертификат сервера подписывается прежним CA, прокси подхватывает его сразу. Уже выданные строки настройки репитера хранят старое имя. Там же можно скачать приватный ключ сервера и импортировать свой: сертификат выпускается на текущее имя с этим ключом.

## Репитер

Группа содержит тунели. Имя группы уникально у владельца, имя тунеля уникально внутри группы. В тунеле несколько репитеров, у каждого свой логин. Репитер публикует в топик своего публичного ключа и подписывается на `#`. Прокси дописывает префикс тунеля и обрезает `#` до этого тунеля, поэтому имя топика в строку настройки не входит. Брокер пускает логин только в топики своего тунеля: соседний тунель на том же узле эти сообщения не читает и не пишет.

Доступ выдаётся на группу. В деталях этого доступа отмечают, на какие тунели он распространяется и с какими правами. Новый тунель в уже выданный доступ сам не входит.

После создания репитера панель один раз показывает строку настройки. Это base64 от JSON:

```json
{"v":1,"host":"localhost","port":8883,"user":"…","pass":"…","ca":"-----BEGIN CERTIFICATE-----\n…"}
```

Wi‑Fi задаётся по USB (115200): `set wifi.ssid`, `set wifi.password`, `set wifi on`. Свою сеть репитер не поднимает. Страница статуса появляется после подключения к роутеру, на выданном адресе, порт 80, логин `admin`. В разделе «Подключение MQTT» строка вставляется целиком: репитер берёт из неё адрес, порт, логин, пароль и сертификат и сам ставит топик публикации равным своему публичному ключу. Повторно пароль не показывается.

## Узлы

В админке, раздел «Узлы»: список, подключение нового Mosquitto (тот же образ, HTTP-auth на этот API, порт наружу не открывать), статусы `open`, `draining`, `offline`, удаление пустого узла и перенос тунеля.

Новый тунель попадает на наименее загруженный узел со статусом `open`. При переносе адрес в репитере не меняется: прокси обрывает текущие сессии, устройства переподключаются на тот же адрес и попадают на новый узел. На время обрыва часть сообщений теряется.

## Состав

- `src/MeshCoreMqtt.Core` — разбор MQTT CONNECT, правила топиков, сертификаты и строка настройки репитера
- `src/MeshCoreMqtt.Api` — группы, тунели, узлы и API панелей
- `src/MeshCoreMqtt.Proxy` — вход MQTT поверх TLS на порту `8883` и перенаправление на узел тунеля
- `src/MeshCoreMqtt.Web` — панели `/app` и `/admin`
- `tests/MeshCoreMqtt.Core.Tests` — проверки ядра
- `docker/` — образы API, прокси, веб-панели и шаблон Mosquitto

## Образы

Пуш в `master` собирает тесты и публикует образы с тегом `edge`. Тег `vX.Y.Z` публикует тот же набор с тегом версии и `latest`, затем открывает релиз.

- `ghcr.io/termin36/meshcore-mqtt-api`
- `ghcr.io/termin36/meshcore-mqtt-proxy`
- `ghcr.io/termin36/meshcore-mqtt-web`

`docker compose up --build` по-прежнему собирает образы локально. Готовые образы подтягиваются так:

```bash
docker compose pull
docker compose up
```
